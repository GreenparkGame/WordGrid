# WordGrid - A Mr Robinson Game

Classroom multiplayer starter project

This is a small full-stack version of WordGrid, based on the current classroom game. Unlike the standalone HTML prototype, this package includes a Node.js server so room codes, player names, the shared 10×10 board, round start, word discoveries and the leaderboard synchronise across devices.

## The files

- `index.html` — the game interface and word-finding interactions.
- `server.js` — room/session API and live game state.
- `dictionary.json` — the bundled English-word dictionary used to validate submissions on the server.
- `package.json` — start command (`npm start`).

## Publish it with Replit (beginner-friendly route)

1. Download and unzip `wordgrid-multiplayer-project.zip` on your computer.
2. Sign in to Replit and create a new **Node.js** app/project.
3. Upload `index.html`, `server.js`, `dictionary.json` and `package.json` into the project’s top-level/root folder (not inside an extra nested folder).
4. In Replit's Secrets / Environment Variables tool, add `OXFORD_APP_ID` and `OXFORD_APP_KEY` using credentials from your Oxford Dictionaries API account. The project requires Oxford validation by default; it will not start rounds until these credentials are present. Do not paste the credentials into `index.html` or share them with pupils. If you are only testing the bundled fallback and understand it is not Oxford-verified, set `OXFORD_REQUIRED=false` instead.
5. Run the app using `npm start`. The preview should open WordGrid and report the active word-checking source on the home screen.
6. Test in two separate browser windows before publishing: in the first, choose **Host a game → Multiplayer → Create classroom game**; in the second, open the preview URL with `?join=THECODE` at the end, enter a username and join. Confirm the host sees the pupil, then start the round and check that both devices show the same board and shared leaderboard.
7. Use Replit’s **Publish/Deploy** flow to create a public web deployment. **Do not use Static hosting**: this project needs the Node.js server to run. Configure the run command as `npm start` and choose a single running server instance because the starter stores active rooms in memory. Replit will give you a public HTTPS URL such as `https://your-app-name.replit.app`; use that published URL with the QR code, not a temporary development/preview URL. Review any publishing charges before confirming.
8. Open the public URL on your phone and test the entire flow again. The QR code generated by the host screen automatically includes the public page address and the current room code.

Replit's publishing documentation explains that published sites receive a public `replit.app` URL, and its static deployment option is intended for static files; WordGrid requires a running server. See https://docs.replit.com/references/publishing/static-deployments and https://docs.replit.com/references/publishing/reserved-vm-deployments.

## Vocabulary and scoring

The year-group selector uses the supplied spelling posters:

- Year 1: common exception words (including the one-letter entries `a` and `i`).
- Year 2: common exception words.
- Years 3 and 4: the supplied combined statutory spelling list is used for both selections.
- Years 5 and 6: the supplied combined statutory spelling list is used for both selections.

The random Years 1–6 option draws from the combined lists. A word in the currently selected focus list earns **2 points per letter**. This includes the host's custom list. Any other accepted dictionary word earns **1 point per letter**. In the random option, the combined spelling lists are the focus list, so a word from any of those lists earns the double bonus. Single-letter words count only when they belong to the selected focus list.

## Host scoring rules

The solo and multiplayer setup screens both include two host controls:

- **Only look for spelling words (toggle):** available when the host selects **My own words**. When switched on, only words from the host's custom spelling list are accepted. Those focus words score double, subject to the minimum scoring length.
- **Minimum scoring word length:** choose 3, 4, 5 or 6 letters. A valid word shorter than the chosen threshold can still be found and shown in the discoveries, but it scores **0 points**. Words at or above the threshold score normally: 1 point per letter, or 2 points per letter when they are in the focus list.

These settings are stored in the multiplayer room and enforced by the server, so pupils cannot change the scoring rules from their own devices. They are also available when the teacher prepares a replay.

## Oxford Dictionaries verification

The project supports the Oxford Dictionaries API for British English (`en-gb`). When API credentials are configured, the Node.js server checks each submitted word and validates custom focus lists against Oxford. The Oxford App ID and App Key must be stored as server secrets named `OXFORD_APP_ID` and `OXFORD_APP_KEY`; they are never placed in the browser code. The project does not cache Oxford responses.

**Oxford verification is required by default.** Until both secrets are configured, the deployed project reports that Oxford checking is unavailable and blocks a new round from starting. To deliberately use the bundled local word list for testing only, set `OXFORD_REQUIRED=false` on the server. That fallback word list is not an official Oxford source and must not be described as Oxford-verified.

Oxford's free Sandbox trial currently allows 500 calls but only for words beginning with the letter A, so it is not enough to verify the full alphabet for a classroom game. A full-access plan is needed for all letters. Oxford's FAQ also says that the Oxford Dictionaries API is distinct from the Oxford English Dictionary (OED); the API provides access to its current English dictionaries, including updated Oxford Dictionary of English content. Oxford says caching or offline storage of API data is only permitted under an Enterprise licence, so this project does not store Oxford lookup results. Review the current Oxford API plan and terms before using it for a class.

## Single-player flow

1. Open WordGrid and choose **Host a game** to reach the setup screen.
2. Choose **Single player**. Choose **Random words** for a mix of vocabulary from Years 1–6, **Choose a year group** for that year's statutory/common exception word list, or **My own words** to enter up to 10 focus words (comma-separated or one per line).
3. Press **Start solo game**. Your chosen focus words are placed on the board where possible, while the broad dictionary still accepts other recognised English words you find. Ordinary dictionary words score one point per letter. Words from the selected year-group list or teacher's own focus list score double (two points per letter). One- and two-letter words from a selected focus list are accepted as well, so the Year 1 and Year 2 common exception words can be found (including 'a' and 'I'). They earn zero points under the default three-letter minimum, unless the host lowers the scoring threshold (minimum options begin at three letters).

## Classroom flow once published

1. Teacher opens the public WordGrid URL on the classroom computer.
2. Teacher chooses **Host a game**, then **Multiplayer**, chooses a word-list type and round length, and creates the room.
3. The teacher displays the QR code and game code on the whiteboard.
4. Pupils scan the code, enter a classroom nickname and press **Join the game**. They appear in the lobby automatically.
5. The teacher presses **Start game** when the class is ready. Everyone receives the same board and timer.
6. As pupils find words, each pupil's score and the live leaderboard update across the room. The server checks submitted words against the bundled dictionary and confirms a valid path through the shared board; ordinary words score one point per letter, while words from the selected vocabulary list score two points per letter.

## End-of-round results and replays

When a classroom round finishes, the host sees the top five pupil usernames and their final points, plus three choices:

- **Back to home screen** closes the teacher's current session view.
- **Play again with the same usernames** keeps pupils in the room, resets all scores and found words, and returns everyone to the lobby.
- **Play again with different usernames** keeps the same room code/QR available but clears the pupil list. Pupils are sent back to the join screen and can scan again using new usernames.

For either replay, the host returns to setup and can change the round length and choose a random Years 1–6 mix, a specific year group, or up to 10 custom spellings. The host then starts the next round when the lobby is ready.

## Important notes

- Pupils should use classroom nicknames or first names only. Do not ask them to enter surnames, email addresses, dates of birth or other personal information.
- Active rooms are held in server memory, expire after two hours of inactivity and are cleared if the server restarts or is redeployed. This is designed for live classroom rounds, not permanent score records.
- Keep one server instance for the starter because room state is in memory. For multi-instance scaling or saved class histories, the app would need a persistent shared database.
- The QR is generated by an external QR image service, so devices need internet access to load the QR image. Pupils can still type the room code if the image is blocked.
